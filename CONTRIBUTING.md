# Contributing

Every library repository has its own CONTRIBUTING.md with its build, test and lint commands. This file is the default for the rest, mainly [saas-issues](https://github.com/Guard-Core/saas-issues).

## Issues

- Search open and closed issues first.
- One report per issue, in English, using the templates.
- Never post credentials, API keys, tokens or payload data that is not yours.
- Vulnerabilities go through [SECURITY.md](SECURITY.md), never a public issue.

## Pull requests

1. Open an issue first, so the change is agreed before code is written. Small fixes with nothing to discuss carry the `no-issue` label instead.
2. The pull request body says `Closes #N` for that issue.
3. Commits are signed and follow Conventional Commits (`feat(scope): ...`, `fix(scope): ...`, `docs: ...`).
4. Every check of the repository passes before a merge.

The [Code of Conduct](CODE_OF_CONDUCT.md) applies everywhere. How decisions are made is in [GOVERNANCE.md](GOVERNANCE.md).
